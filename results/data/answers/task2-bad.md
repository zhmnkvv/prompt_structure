## 5. Подготовка к защите: вероятные вопросы

**Данные**
- *Откуда метки?* От Goodreads через датасет HF. Набор multi-label, я оставил только книги с ровно одним из 4 жанров.
- *Почему базовая модель 0.70?* 70% текстов из Literature & Fiction. Модель, всегда отвечающая этот класс, получает 0.70.
- *Почему stratify?* Чтобы доли классов в train и test совпадали. Иначе в тест могло бы попасть, например, 10 Mystery вместо 22.

**Методика**
- *Почему тест используется один раз?* Если подбирать настройки по тесту, он станет частью обучения и оценка будет завышена. Настройки выбираем по 5-fold CV на train.
- *Как понять, что одна настройка лучше другой?* Разница должна быть больше std в CV и больше пары примеров в тесте. NB против LR C=3 по test accuracy: 0.770 и 0.758, это около 5 текстов из 413, то есть шум.
- *Что такое C?* Обратная сила регуляризации. Большое C — слабее штраф, модель сильнее подгоняется под данные. У тебя C=3 лучше C=1 лучше C=0.3: данным полезна более гибкая модель.
- *Почему NB может обыгрывать LR?* NB хорошо работает на малых данных, а у тебя 1648 текстов на обучение. LR нужно больше данных; это видно и по кривой обучения.
- *Почему bigrams и char n-grams не помогли?* Описания длинные (медиана около 135 слов). Жанр определяется отдельными словами (`murder`, `dragon`, `love`), а лишние признаки добавляют шум. Char n-grams полезнее для языков с богатой морфологией (казахский, русский).

**TF-IDF (он покажет на ячейку!)**

Формула sklearn по умолчанию (`smooth_idf=True`, `norm="l2"`):
- tf = просто число вхождений слова в документ;
- idf(t) = ln((1 + n) / (1 + df(t))) + 1;
- значение до нормировки = tf × idf, потом каждая строка делится на свою L2-норму (корень из суммы квадратов).

Готовые значения для n = 5 документов:

| df | idf |
|---|---|
| 1 | ln(6/2) + 1 = 2.0986 |
| 2 | ln(6/3) + 1 = 1.6931 |
| 3 | ln(6/4) + 1 = 1.4055 |
| 4 | ln(6/5) + 1 = 1.1823 |
| 5 | ln(6/6) + 1 = 1.0000 |

Пример: слово встречается 2 раза в документе и в 1 документе из 5. Тогда сырое значение 2 × 2.0986 = 4.197, затем делим на норму строки. Норму покажет ячейка 41 ("Inspect one TF-IDF cell"). Поменяй там `doc_i` и `word` и потренируйся на 2–3 клетках.

- *Зачем "+1" в числителе и знаменателе?* Как будто есть лишний документ со всеми словами: так не бывает деления на ноль.
- *Зачем "+1" в конце?* Слово из всех документов получает вес 1, а не 0.
- *Почему по учебниковой формуле ln(n/df) не совпадает с sklearn?* Как раз из-за smooth_idf и этого "+1".
- *Зачем L2-нормировка?* Чтобы длинные тексты не получали большие значения просто из-за длины. После нормировки косинусное сходство равно скалярному произведению.

**Поиск и дубликаты**
- *Почему косинус, а не евклидово расстояние?* Косинус смотрит на направление вектора, то есть на состав слов, а не на длину текста.
- *Почему векторайзер для поиска дубликатов обучен только на train?* Чтобы test не влиял на idf: та же логика, что и в честной оценке.
